# Entity-watch admin error messages — clarity fix

## Проблема

Адмін-алерт `⚠️ Тимчасово не вдалось перевірити (мережа/Prozorro, повтор наступного запуску): • {tender_id} — {error}`
(monitor.mjs:382-390) надсилається для двох принципово різних ситуацій, але текстом
не розрізняється:

1. **Watchlist-тендер** (доданий вручну через `/add`) — тимчасова мережева/5xx
   помилка при перевірці тендера, який користувач явно стежить.
2. **Entity-watch кандидат** — бот сам знайшов тендер від відстежуваного замовника
   (`watched_entities.json`) через forward-feed, але не зміг завантажити деталі
   (`fetchTender`), щоб перевірити код ДК (`hasRelevantCpv`, `entity_watch.mjs:130`).
   Релевантність кандидата ще НЕ визначена — фільтр по ДК спрацьовує тільки
   *після* успішного fetch.

Наслідок: користувач бачить повідомлення з "Тимчасово не вдалось перевірити" і не
може зрозуміти, чи це проблема з ботом взагалі, чи з конкретним тендером, чи це
взагалі стосується чогось релевантного. Реальний випадок:
`UA-2026-07-09-007845-a` — кандидат від замовника, який бот моніторить, з кодом ДК,
що не відповідає whitelist (`48`/`72`) — тобто навіть при вдалому fetch тендер
ніколи не згенерував би сповіщення. Повідомлення виглядало як загальний збій бота.

## Рішення

Розрізнити джерело помилки й будувати для кожного окрему текстову секцію
адмін-алерту. Без зміни частоти/логіки надсилання (залишається: одразу, щотика,
поки помилка триває) — лише текст.

### 1. Тег джерела (`monitor.mjs`)

У блоці, що перекладає `watchResult.errors` в загальний `errors[]`
(`monitor.mjs:207-214`), додати `source: 'entity_watch'` до кожного об'єкта.
Помилки з watchlist-циклу (`monitor.mjs:159-163`) тег не отримують (залишаються
"watchlist" за замовчуванням, `source` відсутній).

### 2. Дві секції в адмін-тексті (`monitor.mjs:382-390`)

Розбити `adminErrors` на `watchlistAdminErrors` (без тегу) і
`entityWatchAdminErrors` (`source === 'entity_watch'`). Будувати текст із секцій,
які присутні (одна чи обидві, розділені порожнім рядком):

**Watchlist-секція** (текст лишається як є — уже зрозумілий у контексті "мій
тендер"):
```
⚠️ Тимчасово не вдалось перевірити тендери з твого списку стеження
(мережа/Prozorro, повтор наступного запуску):
  • {tender_id} — {error}
```

**Entity-watch секція** (новий, пояснювальний текст):
```
ℹ️ Не вдалось завантажити деталі тендера від відстежуваного замовника — код ДК
ще не перевірено, спробуємо ще раз наступного запуску:
  • {tender_id} — {error}
```

### Поза скоупом

- Частота/дедуплікація повторних алертів (розглядали окремий підхід із
  лічильником невдалих спроб — відхилено користувачем: логіка залишається
  "надсилати щотика, поки помилка триває").
- Поведінка для watchlist 404 (auto-disable + публічний дайджест) — без змін.
- Feed/backfill-рівневі помилки entity_watch (`source: 'feed'`/`'backfill'`, без
  `tender_id`) потрапляють у ту саму нову entity-watch секцію — вони теж про
  "бот не зміг перевірити щось у межах entity-watch", той самий пояснювальний
  текст їм підходить.
